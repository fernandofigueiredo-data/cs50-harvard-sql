Fundamentos

Os conceitos na ordem em que aparecem nas anotações do curso.

Introdução

Por que usar um banco de dados, quais programas existem e qual linguagem conversa com eles.

Banco de dados × planilha

Uma planilha resolve bem pequenos volumes de dados. O banco de dados passa a ser a melhor escolha quando três fatores pesam:

  • Escala: a quantidade de dados cresce muito além do que uma planilha comporta com conforto.
  • Atualização frequente: os dados mudam o tempo todo e precisam continuar consistentes.
  • Velocidade: as consultas precisam devolver respostas rapidamente, mesmo com muitos dados.

O que é um banco de dados

É um coletor de dados organizados que permite quatro operações básicas: criar, ler, atualizar e deletar dados.

Softwares de banco de dados

Alguns dos programas mais conhecidos para gerenciar bancos de dados:

  • MySQL
  • Oracle
  • PostgreSQL
  • SQLite

complemento da documentação oficial O SQLite é uma biblioteca que funciona sem servidor separado e sem configuração; o banco de dados inteiro fica guardado em um único arquivo em disco.

SQL

SQL significa Linguagem de Consulta Estruturada (Structured Query Language). É a linguagem usada para interagir com os bancos de dados: consultar, inserir, alterar e excluir dados, além de definir a estrutura das tabelas.

Abrir um banco no terminal

No terminal, o programa sqlite3 seguido do nome do arquivo abre o banco de dados. A partir daí, você digita comandos no prompt do SQLite.

sqlite3 {{arquivo.db}}

Resultado esperadoO terminal passa a exibir o prompt sqlite>, pronto para receber instruções SQL e comandos de ponto.

Guia rápido: criar um banco SQLite a partir de um schema

Um roteiro de quatro passos para sair de uma pasta vazia e chegar a um banco com as tabelas definidas em um arquivo .sql.

1. Criar uma pasta para o projeto

mkdir vem de make directory: cria um diretório (pasta). Em seguida, cd entra nele.

mkdir "{{nome_da_pasta}}"
cd "{{nome_da_pasta}}"

2. Criar o arquivo de schema (.sql)

O comando code cria (ou abre) o arquivo no VS Code. Dentro dele, escreva as instruções SQL que definem o banco, como CREATE TABLE.

Se o arquivo ainda não existir, o sqlite3 cria um banco SQLite vazio com esse nome.

4. Carregar o schema no banco

Depois de entrar no SQLite, aparece o prompt sqlite>. Nele, o comando .read executa todas as instruções SQL contidas no arquivo.

Aula 1 · Consultando

Como ler dados de uma tabela: escolher colunas, filtrar linhas, ordenar e resumir resultados.

SELECT

Seleciona dados de uma tabela. O asterisco (*) traz todas as colunas; para trazer só algumas, liste os nomes separados por vírgula.

SELECT * FROM "{{nome_da_tabela}}";
SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}";

LIMIT

Limita a quantidade de linhas devolvidas pela consulta.

SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}" LIMIT {{numero_de_linhas}};

WHERE e operadores de igualdade

WHERE filtra as linhas, mantendo apenas as que satisfazem a condição. Operadores de igualdade:

  • = igual a
  • != diferente de
  • <> diferente de (forma alternativa)
SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}" WHERE "{{coluna_2}}" = {{valor}};
SELECT "{{coluna_1}}" FROM "{{nome_da_tabela}}" WHERE "{{coluna_2}}" != '{{texto}}';
SELECT "{{coluna_1}}" FROM "{{nome_da_tabela}}" WHERE "{{coluna_2}}" <> '{{texto}}';

NOT

Inverte uma condição: mantém as linhas em que a condição é falsa.

SELECT "{{coluna_1}}" FROM "{{nome_da_tabela}}" WHERE NOT "{{coluna_2}}" = '{{texto}}';

AND, OR e parênteses

AND exige que todas as condições sejam verdadeiras; OR exige que pelo menos uma seja. Os parênteses agrupam condições e definem a ordem de avaliação, como na matemática.

SELECT "{{coluna_1}}" FROM "{{nome_da_tabela}}"
WHERE "{{coluna_2}}" = {{valor_1}} OR "{{coluna_2}}" = {{valor_2}};
SELECT "{{coluna_1}}" FROM "{{nome_da_tabela}}"
WHERE ("{{coluna_2}}" = {{valor_1}} OR "{{coluna_2}}" = {{valor_2}})
AND "{{coluna_3}}" != '{{texto}}';
Divergência com a documentação oficial

Um dos exemplos das anotações escreve = valor OR valor, sem repetir a coluna. Pela documentação de expressões do SQLite, cada lado do OR é avaliado separadamente; um número sozinho diferente de zero conta como verdadeiro, então essa forma não filtra como se espera. Repita a coluna em cada comparação, como nos exemplos acima.

sqlite.org/lang_expr.html

NULL

NULL representa um valor que não existe: o dado não está no banco de dados. Para testar se um valor é nulo, use IS NULL; para o contrário, IS NOT NULL.

SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}"
WHERE "{{coluna_2}}" IS NULL;
SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}"
WHERE "{{coluna_2}}" IS NOT NULL;

LIKE: busca por padrões de texto

LIKE compara um texto com um padrão que pode conter curingas:

  • % substitui qualquer sequência de caracteres (inclusive nenhuma);
  • _ substitui exatamente um caractere, útil quando não se sabe uma letra ao certo.
SELECT "{{nome_da_coluna}}" FROM "{{nome_da_tabela}}"
WHERE "{{nome_da_coluna}}" LIKE '%{{texto}}%';
SELECT "{{nome_da_coluna}}" FROM "{{nome_da_tabela}}"
WHERE "{{nome_da_coluna}}" LIKE '{{texto}}%';
SELECT "{{nome_da_coluna}}" FROM "{{nome_da_tabela}}"
WHERE "{{nome_da_coluna}}" LIKE '{{texto}} %';
SELECT "{{nome_da_coluna}}" FROM "{{nome_da_tabela}}"
WHERE "{{nome_da_coluna}}" LIKE '{{inicio}}_{{fim}}';

No primeiro bloco, o texto pode estar em qualquer posição; no segundo, no início; no terceiro, no início e seguido de espaço (uma palavra inteira); no quarto, o _ aceita qualquer caractere naquela posição.

complemento da documentação oficial Por padrão, o LIKE do SQLite não diferencia maiúsculas de minúsculas para letras ASCII.

Comparações: >, <, >=, <=

Operadores de comparação para números, datas em texto e outros valores ordenáveis: maior que, menor que, maior ou igual, menor ou igual. Combine-os com AND para definir um intervalo.

SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}"
WHERE "{{coluna_2}}" >= {{valor_1}} AND "{{coluna_2}}" <= {{valor_2}};
Divergência com a documentação oficial

As anotações escrevem >= valor_1 AND <= valor_2, sem a coluna na segunda comparação. Na sintaxe de expressões do SQLite, cada operador precisa de dois operandos; a coluna deve ser repetida, como no exemplo.

sqlite.org/lang_expr.html

BETWEEN

Forma compacta de filtrar um intervalo de valores.

SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}"
WHERE "{{coluna_2}}" BETWEEN {{valor_1}} AND {{valor_2}};

complemento da documentação oficial Os limites são inclusivos: x BETWEEN y AND z equivale a x >= y AND x <= z.

ORDER BY, ASC e DESC

ORDER BY ordena o resultado por uma ou mais colunas. ASC indica ordem crescente e DESC, decrescente. Com várias colunas, a segunda desempata a primeira.

SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}"
ORDER BY "{{coluna_2}}" LIMIT {{numero_de_linhas}};
SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}"
ORDER BY "{{coluna_2}}" DESC LIMIT {{numero_de_linhas}};
SELECT "{{coluna_1}}", "{{coluna_2}}", "{{coluna_3}}" FROM "{{nome_da_tabela}}"
ORDER BY "{{coluna_2}}" DESC, "{{coluna_3}}" DESC
LIMIT {{numero_de_linhas}};

complemento da documentação oficial Sem ASC nem DESC, a ordem é crescente.

Funções de agregação: COUNT, AVG, MIN, MAX, SUM

Resumem muitas linhas em um único valor: contagem, média, mínimo, máximo e soma.

SELECT COUNT(*) FROM "{{nome_da_tabela}}";
SELECT AVG("{{nome_da_coluna}}") FROM "{{nome_da_tabela}}";
SELECT MIN("{{nome_da_coluna}}") FROM "{{nome_da_tabela}}";
SELECT MAX("{{nome_da_coluna}}") FROM "{{nome_da_tabela}}";
SELECT SUM("{{nome_da_coluna}}") FROM "{{nome_da_tabela}}";

ROUND

Arredonda um número para a quantidade de casas decimais indicada. Costuma envolver uma agregação, como a média.

SELECT ROUND(AVG("{{nome_da_coluna}}"), {{casas_decimais}}) FROM "{{nome_da_tabela}}";

AS

Dá um apelido (alias) a uma coluna do resultado, deixando a saída mais legível.

SELECT ROUND(AVG("{{nome_da_coluna}}"), {{casas_decimais}}) AS "{{nome_do_alias}}"
FROM "{{nome_da_tabela}}";

DISTINCT

Remove valores repetidos do resultado. Dentro de COUNT, conta quantos valores diferentes existem.

SELECT DISTINCT "{{nome_da_coluna}}" FROM "{{nome_da_tabela}}";
SELECT COUNT(DISTINCT "{{nome_da_coluna}}") FROM "{{nome_da_tabela}}";

Combinando filtro, agregação e alias

As cláusulas se somam: é possível filtrar com WHERE, calcular uma média arredondada e nomear o resultado com AS na mesma consulta.

SELECT ROUND(AVG("{{coluna_1}}"), {{casas_decimais}}) AS "{{nome_do_alias}}"
FROM "{{nome_da_tabela}}"
WHERE "{{coluna_2}}" = '{{texto}}';

Aula 2 · Relacionando

Como consultar dados espalhados por várias tabelas relacionadas.

Subconsultas (consultas aninhadas)

Uma consulta pode ficar dentro de outra, entre parênteses. A consulta interna roda primeiro e o resultado dela alimenta a externa. Assim é possível percorrer tabelas relacionadas, inclusive passando por uma tabela intermediária.

SELECT "{{coluna_1}}" FROM "{{nome_da_tabela}}" WHERE "{{coluna_chave}}" = (
    SELECT "{{coluna_fk}}" FROM "{{outra_tabela}}"
    WHERE "{{coluna_2}}" = '{{texto}}'
);
Ver exemplo com três níveis

Três tabelas: a interna localiza uma chave, a do meio a usa na tabela intermediária e a externa traz o dado final.

SELECT "{{coluna_1}}" FROM "{{tabela_a}}" WHERE "{{coluna_chave}}" = (
    SELECT "{{coluna_fk_a}}" FROM "{{tabela_de_juncao}}" WHERE "{{coluna_fk_b}}" = (
        SELECT "{{coluna_chave}}" FROM "{{tabela_b}}"
        WHERE "{{coluna_2}}" = '{{texto}}'
    )
);

IN

Use IN quando a comparação envolve mais de um valor, por exemplo quando a subconsulta devolve várias linhas.

SELECT "{{coluna_1}}" FROM "{{nome_da_tabela}}" WHERE "{{coluna_chave}}" IN (
    SELECT "{{coluna_fk}}" FROM "{{outra_tabela}}"
    WHERE "{{coluna_2}}" = {{valor}}
);

INNER JOIN, ON e notação de ponto

JOIN (ou INNER JOIN) junta tabelas lado a lado. ON diz quais colunas devem casar, e a notação de ponto (tabela.coluna) indica de qual tabela vem cada coluna. As linhas sem correspondência entre as tabelas ficam de fora do resultado.

SELECT * FROM "{{tabela_a}}"
JOIN "{{tabela_b}}" ON "{{tabela_b}}"."{{coluna_chave}}" = "{{tabela_a}}"."{{coluna_chave}}";

LEFT JOIN, RIGHT JOIN e FULL JOIN

As anotações listam essas três junções.

complemento da documentação oficial Diferente do INNER JOIN, elas mantêm linhas sem correspondência e preenchem as colunas ausentes com NULL: LEFT JOIN preserva todas as linhas da tabela da esquerda, RIGHT JOIN todas as da direita e FULL JOIN as de ambas. RIGHT e FULL são aceitos a partir do SQLite 3.39.0.

SELECT * FROM "{{tabela_a}}"
LEFT JOIN "{{tabela_b}}" ON "{{tabela_b}}"."{{coluna_chave}}" = "{{tabela_a}}"."{{coluna_chave}}";
SELECT * FROM "{{tabela_a}}"
RIGHT JOIN "{{tabela_b}}" ON "{{tabela_b}}"."{{coluna_chave}}" = "{{tabela_a}}"."{{coluna_chave}}";
SELECT * FROM "{{tabela_a}}"
FULL JOIN "{{tabela_b}}" ON "{{tabela_b}}"."{{coluna_chave}}" = "{{tabela_a}}"."{{coluna_chave}}";

NATURAL JOIN

Junta as tabelas automaticamente, sem precisar de ON.

SELECT * FROM "{{tabela_a}}"
NATURAL JOIN "{{tabela_b}}";
Divergência com a documentação oficial

As anotações dizem que o NATURAL JOIN une “as tabelas iguais”. Pela documentação, ele usa como critério as colunas que têm o mesmo nome nas duas tabelas, como se houvesse um USING com todas elas.

sqlite.org/lang_select.html

UNION, INTERSECT e EXCEPT

Combinam o resultado de duas consultas que tenham o mesmo número de colunas. Um texto fixo com AS pode identificar de qual consulta veio cada linha.

SELECT "{{nome_da_coluna}}" FROM "{{tabela_a}}"
UNION
SELECT "{{nome_da_coluna}}" FROM "{{tabela_b}}";
SELECT '{{texto_1}}' AS "{{nome_do_alias}}", "{{nome_da_coluna}}" FROM "{{tabela_a}}"
UNION
SELECT '{{texto_2}}' AS "{{nome_do_alias}}", "{{nome_da_coluna}}" FROM "{{tabela_b}}";

complemento da documentação oficial UNION junta as linhas das duas consultas sem repetições; INTERSECT devolve só as linhas presentes nas duas; EXCEPT devolve as linhas da primeira que não aparecem na segunda.

GROUP BY e HAVING

GROUP BY reúne em grupos as linhas que têm o mesmo valor em uma coluna, para que uma agregação seja calculada por grupo. HAVING filtra os grupos pelo resultado da agregação.

SELECT "{{coluna_1}}", ROUND(AVG("{{coluna_2}}"), {{casas_decimais}}) AS "{{nome_do_alias}}"
FROM "{{nome_da_tabela}}"
GROUP BY "{{coluna_1}}"
HAVING "{{nome_do_alias}}" > {{valor}}
ORDER BY "{{nome_do_alias}}" DESC;

complemento da documentação oficial WHERE filtra linhas antes do agrupamento; HAVING é avaliado depois, sobre cada grupo.

Aula 3 · Desenhando

Como projetar a estrutura do banco: tipos de dados, criação de tabelas, relacionamentos e restrições.

Tipos de dados

O SQLite trabalha com cinco tipos de dados:

TipoGuarda
NULLAusência de valor.
INTEGERNúmeros inteiros.
REALNúmeros com casas decimais (ponto flutuante).
TEXTTexto.
BLOBDados binários guardados exatamente como foram fornecidos.

complemento da documentação oficial A documentação chama esses cinco tipos de classes de armazenamento e descreve o conteúdo de cada um como na tabela acima.

Afinidades

Cada coluna tem uma afinidade de tipo: TEXT, NUMERIC, INTEGER, REAL ou BLOB.

complemento da documentação oficial A afinidade é o tipo preferido da coluna: o SQLite tenta converter os valores para ela ao armazená-los, mas qualquer coluna ainda pode guardar qualquer tipo de dado. A afinidade é deduzida do tipo declarado: se contém “INT”, é INTEGER; se contém “CHAR”, “CLOB” ou “TEXT”, é TEXT; se contém “BLOB” ou se nenhum tipo foi declarado, é BLOB; se contém “REAL”, “FLOA” ou “DOUB”, é REAL; nos demais casos, NUMERIC.

a) Criar tabela

Abra (ou crie) o banco com sqlite3 e use CREATE TABLE com o nome da tabela e a lista de colunas entre parênteses.

sqlite3 {{arquivo.db}}
CREATE TABLE "{{nome_da_tabela}}" (
    "{{coluna_1}}",
    "{{coluna_2}}"
);

Depois de criar as tabelas, .schema mostra o resultado.

complemento da documentação oficial Uma coluna declarada sem tipo, como acima, recebe afinidade BLOB.

Divergência com a documentação oficial

As anotações mostram o terminal perguntando se o arquivo deve ser criado ([y/n]). A documentação do sqlite3 não prevê essa pergunta: se o arquivo não existe, um novo banco é criado automaticamente. A confirmação provavelmente vem do ambiente usado no curso.

c) Relacionar tabelas

Para relacionar duas tabelas, crie uma terceira cujas colunas guardam as chaves de cada uma. Cada linha dessa tabela de junção liga uma linha de uma tabela a uma linha da outra.

CREATE TABLE "{{tabela_de_juncao}}" (
    "{{coluna_fk_a}}",
    "{{coluna_fk_b}}"
);

DROP TABLE remove a tabela e todos os dados dela.

g) Restrições de tabela: PRIMARY KEY e FOREIGN KEY

A chave primária (PRIMARY KEY) identifica cada linha de forma única. A chave estrangeira (FOREIGN KEY) aponta, com REFERENCES, para a chave primária de outra tabela, criando o relacionamento.

CREATE TABLE "{{nome_da_tabela}}" (
    "{{coluna_chave}}" INTEGER,
    "{{coluna_1}}" TEXT,
    PRIMARY KEY ("{{coluna_chave}}")
);
Ver tabela de junção com duas chaves estrangeiras 
CREATE TABLE "{{tabela_de_juncao}}" (
    "{{coluna_fk_a}}" INTEGER,
    "{{coluna_fk_b}}" INTEGER,
    FOREIGN KEY ("{{coluna_fk_a}}") REFERENCES "{{tabela_a}}" ("{{coluna_chave}}"),
    FOREIGN KEY ("{{coluna_fk_b}}") REFERENCES "{{tabela_b}}" ("{{coluna_chave}}")
);

h) Restrições de coluna: NOT NULL, UNIQUE, CHECK e DEFAULT

Restrições escritas logo após o tipo da coluna. Segundo as anotações, não se aplicam às colunas que contêm chaves primária e estrangeira.

  • NOT NULL: impede que a coluna receba valores nulos.
  • UNIQUE: proíbe valores duplicados na mesma coluna.
  • CHECK: valida uma condição antes de permitir a inserção ou a atualização.
  • DEFAULT: define um valor padrão automático caso nenhum valor seja inserido.
"{{nome_da_coluna}}" NUMERIC NOT NULL CHECK ("{{nome_da_coluna}}" != {{valor}}),
"{{nome_da_coluna}}" TEXT NOT NULL CHECK ("{{nome_da_coluna}}" IN ('{{texto_1}}', '{{texto_2}}')),
"{{nome_da_coluna}}" NUMERIC NOT NULL DEFAULT CURRENT_TIMESTAMP
"{{nome_da_coluna}}" TEXT UNIQUE
Divergência com a documentação oficial

A documentação registra que, por compatibilidade com versões antigas, PRIMARY KEY não implica NOT NULL no SQLite, exceto em colunas INTEGER PRIMARY KEY e em tabelas WITHOUT ROWID. Em chaves primárias de outros tipos, declarar NOT NULL pode ser necessário.

sqlite.org/lang_createtable.html

10) Alterando tabelas

ALTER TABLE modifica uma tabela existente: renomeia a tabela, adiciona, renomeia ou remove colunas.

ALTER TABLE "{{nome_da_tabela}}" RENAME TO "{{novo_nome}}";
ALTER TABLE "{{nome_da_tabela}}" ADD COLUMN "{{nome_da_coluna}}" TEXT;
ALTER TABLE "{{nome_da_tabela}}" RENAME COLUMN "{{nome_da_coluna}}" TO "{{novo_nome}}";
ALTER TABLE "{{nome_da_tabela}}" DROP COLUMN "{{nome_da_coluna}}";

Inserir, excluir e atualizar

Itens 11 a 13 das anotações: como gravar, apagar e modificar dados, incluindo importação de CSV, gatilhos e exclusão lógica.

11. INSERT

INSERT INTO grava novas linhas. Liste as colunas e, em VALUES, os valores na mesma ordem. Várias linhas podem ser inseridas de uma vez, separadas por vírgula.

INSERT INTO "{{nome_da_tabela}}" ("{{coluna_1}}", "{{coluna_2}}", "{{coluna_3}}")
VALUES ('{{texto}}', NULL, {{valor}});
INSERT INTO "{{nome_da_tabela}}" ("{{coluna_1}}", "{{coluna_2}}", "{{coluna_3}}")
VALUES
('{{texto_1}}', 1, NULL),
('{{texto_2}}', 2, '{{texto}}');

Importar CSV

O comando de ponto .import carrega um arquivo CSV em uma tabela. Com --skip 1, a primeira linha (o cabeçalho) é ignorada.

.import --csv --skip 1 {{arquivo.csv}} {{nome_da_tabela}}

Outra forma: importar para uma tabela temporária, copiar só as colunas desejadas com INSERT INTO … SELECT e depois excluir a temporária.

.import --csv {{arquivo.csv}} {{tabela_temporaria}}
INSERT INTO "{{nome_da_tabela}}" ("{{coluna_1}}", "{{coluna_2}}", "{{coluna_3}}")
SELECT "{{coluna_1}}", "{{coluna_2}}", "{{coluna_3}}" FROM "{{tabela_temporaria}}";
DROP TABLE "{{tabela_temporaria}}";

complemento da documentação oficial Se a tabela de destino ainda não existe, o .import a cria e usa a primeira linha do CSV como nomes das colunas; por isso a segunda forma dispensa --skip.

12. DELETE

DELETE FROM exclui as linhas que atendem à condição do WHERE. A condição pode usar uma subconsulta.

DELETE FROM "{{nome_da_tabela}}"
WHERE "{{nome_da_coluna}}" = '{{texto}}';
DELETE FROM "{{tabela_de_juncao}}"
WHERE "{{coluna_fk_a}}" = (
    SELECT "{{coluna_chave}}"
    FROM "{{tabela_a}}"
    WHERE "{{coluna_1}}" = '{{texto}}'
);

complemento da documentação oficial Sem WHERE, todas as linhas da tabela são excluídas.

ON DELETE: o que fazer quando a chave referenciada é excluída

É possível definir a ação tomada quando um ID referenciado por uma chave estrangeira é excluído, com ON DELETE seguido da ação:

  • ON DELETE RESTRICT: impede a exclusão de IDs caso ela viole a restrição de chave estrangeira.
  • ON DELETE NO ACTION: permite a exclusão de IDs referenciados sem realizar nenhuma ação adicional.
  • ON DELETE SET NULL: permite a exclusão e define como NULL as referências da chave estrangeira.
  • ON DELETE SET DEFAULT: igual ao anterior, mas usa um valor padrão em vez de NULL.
  • ON DELETE CASCADE: permite a exclusão e apaga, em cascata, as linhas que fazem referência à chave excluída.
FOREIGN KEY ("{{coluna_fk_a}}") REFERENCES "{{tabela_a}}" ("{{coluna_chave}}") ON DELETE CASCADE

Com CASCADE nas chaves estrangeiras da tabela de junção, um DELETE na tabela referenciada não gera erro e propaga a exclusão para as linhas ligadas a ela.

DELETE FROM "{{tabela_a}}"
WHERE "{{coluna_1}}" = '{{texto}}';

complemento da documentação oficial As restrições de chave estrangeira vêm desativadas por padrão e precisam ser ligadas em cada conexão:

PRAGMA foreign_keys = ON;
Divergência com a documentação oficial

Sobre NO ACTION, a documentação explica que nenhuma ação especial é executada, mas a restrição continua valendo: com as chaves estrangeiras ativadas, a exclusão que deixar referências órfãs falha. A diferença para RESTRICT é o momento da verificação (RESTRICT checa na hora; NO ACTION, ao fim da instrução).

sqlite.org/foreignkeys.html

13. UPDATE

UPDATE … SET altera valores de linhas existentes; o WHERE escolhe quais linhas. Tanto o novo valor quanto a condição podem vir de subconsultas.

UPDATE "{{nome_da_tabela}}" SET "{{nome_da_coluna}}" = {{valor}}
WHERE {{condicao}};
Ver exemplo com subconsultas no SET e no WHERE 
UPDATE "{{tabela_de_juncao}}"
SET "{{coluna_fk_a}}" = (
    SELECT "{{coluna_chave}}"
    FROM "{{tabela_a}}"
    WHERE "{{coluna_1}}" = '{{texto_1}}'
)
WHERE "{{coluna_fk_b}}" = (
    SELECT "{{coluna_chave}}"
    FROM "{{tabela_b}}"
    WHERE "{{coluna_1}}" = '{{texto_2}}'
);

complemento da documentação oficial Sem WHERE, todas as linhas da tabela são alteradas.

TRIM, UPPER, LOWER e LIKE na limpeza de dados

Funções de texto ajudam a padronizar dados com UPDATE:

  • trim: remove espaços do início e do fim;
  • upper / lower: deixa tudo em maiúsculas / minúsculas;
  • LIKE: encontra valores aproximados para corrigi-los de uma vez.
UPDATE "{{nome_da_tabela}}" SET "{{nome_da_coluna}}" = trim("{{nome_da_coluna}}");
UPDATE "{{nome_da_tabela}}" SET "{{nome_da_coluna}}" = upper("{{nome_da_coluna}}");
UPDATE "{{nome_da_tabela}}" SET "{{nome_da_coluna}}" = lower("{{nome_da_coluna}}");
UPDATE "{{nome_da_tabela}}" SET "{{nome_da_coluna}}" = '{{texto}}'
WHERE "{{nome_da_coluna}}" LIKE '{{padrao}}%';

TRIGGERS (gatilhos)

Um gatilho executa instruções automaticamente quando ocorre um INSERT, UPDATE ou DELETE em uma tabela, antes (BEFORE) ou depois (AFTER) do evento. O corpo fica entre BEGIN e END. OLD dá acesso aos valores da linha antes da mudança, e NEW, aos valores novos.

CREATE TRIGGER "{{nome_do_gatilho}}"
BEFORE DELETE ON "{{nome_da_tabela}}"
BEGIN
    INSERT INTO "{{tabela_de_registro}}" ("{{coluna_1}}", "{{coluna_2}}")
    VALUES (OLD."{{coluna_1}}", '{{texto}}');
END;
CREATE TRIGGER "{{nome_do_gatilho}}"
AFTER INSERT ON "{{nome_da_tabela}}"
BEGIN
    INSERT INTO "{{tabela_de_registro}}" ("{{coluna_1}}", "{{coluna_2}}")
    VALUES (NEW."{{coluna_1}}", '{{texto}}');
END;

Os eventos possíveis são BEFORE/AFTER combinados com DELETE, UPDATE ou INSERT.

complemento da documentação oficial NEW existe em gatilhos de INSERT e UPDATE; OLD, em gatilhos de UPDATE e DELETE.

Soft deletions (exclusão lógica)

Em vez de apagar a linha, marca-se a linha como excluída em uma coluna própria. Os dados continuam no banco e as consultas ignoram as linhas marcadas.

ALTER TABLE "{{nome_da_tabela}}"
ADD COLUMN "{{coluna_de_exclusao}}" INTEGER DEFAULT 0;
UPDATE "{{nome_da_tabela}}"
SET "{{coluna_de_exclusao}}" = 1
WHERE {{condicao}};
SELECT * FROM "{{nome_da_tabela}}"
WHERE "{{coluna_de_exclusao}}" != 1;

Visualizações

Itens 14 a 18 das anotações: consultas salvas como visões (views), CTEs e usos práticos de visões.

14. CREATE VIEW e CREATE TEMPORARY VIEW

Uma visão é uma consulta salva com um nome, que depois pode ser usada como se fosse uma tabela. O caminho é: 1) escrever a consulta; 2) colocá-la depois de CREATE VIEW … AS.

CREATE VIEW "{{nome_da_visao}}" AS
SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}";
CREATE TEMPORARY VIEW "{{nome_da_visao}}" AS
SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}";

complemento da documentação oficial A visão temporária fica no banco temporário da conexão e deixa de existir quando a conexão é fechada. Visões são somente leitura no SQLite: para inserir, alterar ou excluir “através” delas, usam-se gatilhos INSTEAD OF (item 18).

15. CTE (Common Table Expression): WITH

A cláusula WITH define, antes da consulta principal, uma ou mais consultas nomeadas que podem ser usadas como tabelas.

WITH "{{nome_da_cte}}" AS (
    SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}"
)
SELECT "{{coluna_1}}" FROM "{{nome_da_cte}}";
WITH "{{cte_1}}" AS (
    SELECT "{{coluna_1}}" FROM "{{tabela_a}}"
), "{{cte_2}}" AS (
    SELECT "{{coluna_1}}" FROM "{{tabela_b}}"
)
SELECT * FROM "{{cte_1}}" JOIN "{{cte_2}}" USING ("{{coluna_1}}");

complemento da documentação oficial Uma CTE funciona como uma visão temporária que existe só durante uma única instrução SQL.

16. Particionamento

Visões podem dividir uma tabela grande em recortes, um por valor de uma coluna.

CREATE VIEW "{{nome_da_visao}}" AS
SELECT "{{coluna_1}}", "{{coluna_2}}" FROM "{{nome_da_tabela}}"
WHERE "{{coluna_3}}" = {{valor}};

17. Segurança: anonimizar dados com uma visão

Uma visão pode expor só as colunas necessárias e trocar uma coluna sensível por um texto fixo, de modo que quem consulta a visão não vê o dado original.

CREATE VIEW "{{nome_da_visao}}" AS
SELECT "{{coluna_1}}", "{{coluna_2}}", '{{texto}}' AS "{{coluna_sensivel}}"
FROM "{{nome_da_tabela}}";

18. Soft deletions em visões: gatilhos INSTEAD OF

Combina exclusão lógica, visão e gatilhos: a visão mostra só as linhas não marcadas, e gatilhos INSTEAD OF transformam um DELETE ou INSERT feito na visão em operações na tabela original. FOR EACH ROW executa o gatilho para cada linha afetada; WHEN define uma condição para que ele rode.

ALTER TABLE "{{nome_da_tabela}}"
ADD COLUMN "{{coluna_de_exclusao}}" INTEGER DEFAULT 0;
CREATE VIEW "{{nome_da_visao}}" AS
SELECT "{{coluna_chave}}", "{{coluna_1}}", "{{coluna_2}}"
FROM "{{nome_da_tabela}}"
WHERE "{{coluna_de_exclusao}}" = 0;
Gatilho que converte DELETE na visão em exclusão lógica 
CREATE TRIGGER "{{nome_do_gatilho}}"
INSTEAD OF DELETE ON "{{nome_da_visao}}"
FOR EACH ROW
BEGIN
    UPDATE "{{nome_da_tabela}}" SET "{{coluna_de_exclusao}}" = 1
    WHERE "{{coluna_chave}}" = OLD."{{coluna_chave}}";
END;

Com o gatilho criado, uma exclusão feita na visão apenas marca a linha na tabela:

DELETE FROM "{{nome_da_visao}}"
WHERE "{{coluna_1}}" = '{{texto}}';
Gatilho de INSERT quando a linha já existe (reativa) 
CREATE TRIGGER "{{nome_do_gatilho}}"
INSTEAD OF INSERT ON "{{nome_da_visao}}"
FOR EACH ROW
WHEN NEW."{{coluna_2}}" IN (
    SELECT "{{coluna_2}}" FROM "{{nome_da_tabela}}"
)
BEGIN
    UPDATE "{{nome_da_tabela}}"
    SET "{{coluna_de_exclusao}}" = 0
    WHERE "{{coluna_2}}" = NEW."{{coluna_2}}";
END;
Gatilho de INSERT quando a linha é nova (insere) 
CREATE TRIGGER "{{nome_do_gatilho}}"
INSTEAD OF INSERT ON "{{nome_da_visao}}"
FOR EACH ROW
WHEN NEW."{{coluna_2}}" NOT IN (
    SELECT "{{coluna_2}}" FROM "{{nome_da_tabela}}"
)
BEGIN
    INSERT INTO "{{nome_da_tabela}}" ("{{coluna_1}}", "{{coluna_2}}")
    VALUES (NEW."{{coluna_1}}", NEW."{{coluna_2}}");
END;

19. Índices

Um índice organiza os valores de uma coluna para acelerar as buscas por ela.

Para verificar se a pesquisa ficou mais rápida, coloque EXPLAIN QUERY PLAN antes da consulta.

SELECT * FROM "{{nome_da_tabela}}" WHERE "{{nome_da_coluna}}" = '{{texto}}';

complemento da documentação oficial Na saída, SCAN indica leitura da tabela inteira; SEARCH … USING INDEX indica que um índice está sendo usado.

21. Transações: BEGIN TRANSACTION

Uma transação agrupa várias instruções para que sejam aplicadas juntas. COMMIT confirma as alterações; ROLLBACK desfaz tudo o que foi feito desde o BEGIN, por exemplo quando uma das instruções provoca erro de restrição.

A) COMMIT

BEGIN TRANSACTION;
UPDATE "{{nome_da_tabela}}" SET "{{nome_da_coluna}}" = "{{nome_da_coluna}}" + {{valor}} WHERE "{{coluna_chave}}" = 2;
UPDATE "{{nome_da_tabela}}" SET "{{nome_da_coluna}}" = "{{nome_da_coluna}}" - {{valor}} WHERE "{{coluna_chave}}" = 1;
COMMIT;

B) ROLLBACK

BEGIN TRANSACTION;
UPDATE "{{nome_da_tabela}}" SET "{{nome_da_coluna}}" = "{{nome_da_coluna}}" + {{valor}} WHERE "{{coluna_chave}}" = 2;
UPDATE "{{nome_da_tabela}}" SET "{{nome_da_coluna}}" = "{{nome_da_coluna}}" - {{valor}} WHERE "{{coluna_chave}}" = 1; -- provoca erro de restrição
ROLLBACK;

C) EXCLUSIVE

BEGIN EXCLUSIVE TRANSACTION;

complemento da documentação oficial Fora do modo WAL, uma transação EXCLUSIVE impede que outras conexões leiam o banco enquanto ela está em andamento. Sem BEGIN, cada instrução já roda em uma transação própria, confirmada automaticamente ao terminar.
